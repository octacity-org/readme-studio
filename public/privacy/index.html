Readme Studio Privacy

Readme Studio is local first. You can write, preview, import, and export Markdown without creating an account or sending the draft to a Readme Studio application database.

Data kept in your browser

The current README draft is automatically saved in local browser storage so it can survive a refresh or a later visit on the same browser profile. Readme Studio does not provide cloud draft synchronization. The site does not set its own application cookies.

If you connect GitHub, the browser also stores the GitHub account summary, an encrypted Readme Studio session token, and its expiration time. Temporary OAuth state and PKCE verification values are kept in session storage during sign-in. The application session expires after approximately 30 minutes. You can remove locally held information by signing out and clearing site data in your browser.

Optional GitHub access

GitHub authorization is not required for the core editor. If you choose to connect, GitHub asks you to approve repository and workflow access. The Cloudflare Worker exchanges the OAuth code, verifies the GitHub account, and returns a short-lived encrypted session token. The encrypted token contains the GitHub access credential and account identifiers needed to make authorized requests; it is stored by the browser and decrypted by the Worker when an authorized action is requested.

Depending on the action you choose, Readme Studio may request your account profile, repository list, repository README, or contribution data from GitHub. Publishing sends the selected repository, branch, commit message, README content, and generated workflow files through the Worker to GitHub. The Worker has no application database and does not intentionally persist these documents or GitHub credentials after processing the request.

Infrastructure and external content

The public application is hosted on GitHub Pages, and the optional API runs on Cloudflare Workers. Cloudflare observability is enabled for the Worker, so Cloudflare may process request metadata, operational logs, and error information according to the service configuration and Cloudflare’s terms. Access tokens and README contents are not deliberately written to application logs by Readme Studio.

README previews and builder tools can load images or generated content from third-party services such as Shields.io, GitHub, and profile-card providers. When the browser requests those resources, the provider may receive ordinary network information such as the IP address, user agent, requested URL, and referral information. Those requests are governed by the respective provider’s policies.

Your choices

  • Use the editor without connecting GitHub.
  • Review GitHub’s authorization screen before granting access.
  • Sign out of Readme Studio and revoke the OAuth application from GitHub settings when access is no longer wanted.
  • Clear browser site data to remove the local draft and stored session information.
  • Avoid previewing third-party images when you do not want the browser to contact their providers.

For privacy questions, use the guidance on the contact page. Never post OAuth codes, session tokens, private README content, or repository credentials in a public issue.
