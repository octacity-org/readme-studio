Support and feedback

Contact Readme Studio

The public GitHub repository is the primary contact point for product questions, reproducible bugs, feature ideas, and documentation improvements.

Get product help

Before opening a report, check the existing issues to see whether the behavior has already been discussed. For a new problem, include the browser and operating system, what you expected to happen, what happened instead, and the shortest sequence that reproduces it. Screenshots are useful for layout or rendering problems, but remove repository secrets and personal information first.

Open or review a GitHub issue. The same tracker can be used for focused feature requests and compatibility reports.

Privacy questions

The privacy page explains browser storage, optional GitHub authorization, the Cloudflare Worker, external preview resources, and available user controls. If something remains unclear, open an issue describing the question without including access tokens, private repository content, OAuth codes, or other sensitive material.

Readme Studio does not currently operate a separate customer-support inbox or telephone line. Publishing a direct, maintained contact route is more useful than listing an address that is not actively monitored.

Security concerns

Do not publish exploitable security details, credentials, or private data in a public issue. Use the repository owner’s available private GitHub contact or security-reporting options when possible. A useful report identifies the affected URL or component, explains the impact, and provides enough detail for the behavior to be reproduced safely.
